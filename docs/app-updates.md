# 应用更新

在「设置 → 检查更新」查看 GitHub 上的最新正式版。仅在打开这个页面或点击「重新检查」时联网；不检查草稿、预发布版，也不降级到较旧版本。应用本体更新与独立插件更新分别处理。

- Android 自动选择当前安装架构的 APK，下载并校验后调起系统安装界面。第一次需要允许聚阅安装应用；安装还需要系统确认。安装前检查包名、签名和版本号，固定签名版本可覆盖更新，书架、历史和插件保留。
- Windows 下载同版本的完整 ZIP，准备并校验文件后，点击「安装并重启」。更新助手等待原进程退出，再替换程序文件并重新打开；替换失败时恢复已修改的文件。用户数据目录不参与替换。程序目录必须可写，受保护的位置可改用发布页下载。
- 当前 iOS 发布的是未签名 IPA，可以检查新版本和打开下载页，安装仍需原来的签名或侧载工具。不能直接调起类似 Android 的覆盖安装。
- 其他平台提供发布页入口。

更新读取本项目的 GitHub Release API，安装包大小及 SHA-256 使用 GitHub 提供的资产信息。只接受本项目对应版本的固定文件名；没有安装包或校验信息时显示等待发布，不从其他平台或旧版本取包。下载允许 GitHub 官方文件服务器的 HTTPS 重定向，保留正常证书验证。Windows 沿用系统 HTTP(S) 代理，无需额外配置更新服务。

发布者需上传 `FusionReader-版本-windows-x64.zip`、`FusionReader-版本-android-架构.apk`，并将完成的 Release 设为正式版。发布新功能时递增 `pubspec.yaml` 的版本；Android 保持原有固定签名密钥和递增的构建号。新客户端首次安装仍使用现有下载方式，之后才可使用应用内更新。

Windows 更新下载和回滚副本位于独立临时目录。取消下载或关闭更新页会清理未安装内容；后续更新会清理已完成的更新任务。Android 缓存为系统安装临时保留，后续下载会清理超过一天的旧任务。备份仍采用项目原有的仅保留最新一份策略。

验证包括版本和平台匹配、损坏下载、重定向限制、取消下载、ZIP 路径及链接检查、安装授权重试和 iOS 界面。Windows 助手通过独立文件夹测试验证正常替换及 DLL 锁定后的回滚，不修改正在使用的程序。

```sh
flutter test test/app_update_test.dart
python -m unittest discover -s test -p windows_updater_test.py
```
